02 / THREE CHECK TYPES

三档是三类检查，可叠加、可分别调频

COUNT是所有表的基础；核心指标和抽样按表独立启用。同一张表可以同时开启三类，抽样表不要求一定配置指标。

校验档位检查方式跨云返回能发现 / 不能证明
① 分区行数
所有表		每个已确认逻辑分区执行准确COUNT(*)；无分区按ALL整表。每个范围一条计数及执行状态。发现数量差异；同数缺行/多行抵消、字段改错可能漏检。
② 分区指标
指定核心表		按分区SUM指定字段；或GROUP BY有限维度后做COUNT、SUM等。每个范围的一条或多条分组指标记录。发现聚合/分布差异；金额对调、正负抵消仍可能相同。
③ 抽样指纹
指定表		SR端按稳定完整键选约1/1000样本；ECS比对键集合与约定列指纹。样本键与约定列；完成适配后才考虑仅返回键与指纹。发现命中样本的内容差异；未命中的记录不受内容保证。

指标不只是填一个字段名

例如：订单表按日期分区，计算订单数、SUM(pay_amount)；再按status分组看订单数与金额。每个求和字段同时记录COUNT(字段)或NULL数，保留SUM为NULL的状态，不把NULL直接变成0。

统一比较口径

字段映射、过滤条件、分组维度、NULL、金额精度和时间语义两端一致。整数、DECIMAL默认零差异，浮点按字段约定容差。

分组也有传输预算

按状态、渠道等受控维度分组；按订单ID分组可能接近全量明细。比较双方分组键并集，单侧缺组不可漏掉。

分区文件损坏：本方案不是全副本健康检测。COUNT可能只读取部分列或使用引擎优化，抽样也不覆盖全部数据页；COUNT正常不代表所有字段文件可读。怀疑损坏的范围应获批执行定向列读取/更深检查，并结合运维健康检查；不能把失败当0行。

本期边界不变：只有SR数据与元信息；DataWorks尚未开通，无血缘或生产加工任务信息，无法保证历史范围不变或协调停写。不自动修复数据、重跑业务任务、停写或切流。

三档分别标注COUNT、指标、SAMPLE证据，不能合并成“全量内容一致”。02 / 09
03 / SIMPLIFIED DEPLOYMENT

一台阿里校验ECS，连接两端StarRocks

重计算尽量留在数据库，集中程序负责调度、收结果、样本规范化和比对。华为侧不再默认新增校验主机。

蓝色虚线：查询 / 备份交互　　绿色：结果返回　　节点悬停可查看标签。

可以省掉Worker的前提

两端版本支持同语义的服务端过滤；专线可达只读端点；结果量受控；允许样本字段与分组值进入阿里校验ECS。

何时再保留华为Worker

样本内容不允许跨云、深查需大量明细、本地规范化不可替代，或跨云读取不可靠时。Worker可本地处理后传获批摘要，但不能消除SR扫描成本。

安全变化：两端只读凭证集中到ECS受控保存，分源隔离；使用私网白名单及经验证的TLS连接（校验证书与主机名）。不支持时先补批准的加密接入，不关闭校验。PG不对公网开放，主机不与FE/BE混部。

相比双Worker减少部署运维；并非跨云流量一定比双Worker更低。03 / 09
04 / SCOPE & RULE INPUT

客户给表和规则，程序确认分区范围

顺序仍是：表存在 → 逻辑结构 → 范围清单 → COUNT → 配置的指标 / 抽样。缺表、无权限、未知范围不能跳过后算完成。

需区分的字段如何选择订单表示例
分区 / 范围字段读取真实建表定义、分区表达式和边界；无分区默认ALL。按order_date对应的日分区核对。不根据dt、updated_at等列名猜测。
指标字段与维度客户指定SUM字段、分组维度与过滤口径。SUM(pay_amount)，按status分组COUNT与SUM。
抽样键 / 比较列抽样用稳定、非空、可靠唯一完整键；内容用已约定可比较列。用order_id选样本，比较完整键、金额、状态等；不只对order_id求指纹。
范围清单取并集，而不是交集。两端当前元数据＋已登记历史范围共同生成清单，包含单侧缺失、NULL、范围外和审批排除项。不同物理分区可映射同一逻辑范围；不能用物理分区ID配对。

基础名单仍可沿用v1.2的七列CSV

layer,source_db,source_table,target_db,target_table,priority,enabled ODS,ods,orders,ods,orders,70,true DWD,dwd,order_detail,dwd,order_detail,90,true

示例数据，文件不含凭证。可单文件或按ODS、DWD拆分文件。COUNT默认纳入全部启用表；指标与抽样使用独立规则记录关联表资产，不将任意SQL塞进CSV。

新增：指标规则

指标名称、字段/函数、分组维度、结构化过滤、NULL与精度、容差、执行频率、最大分组数/返回字节、负责人。

新增：抽样规则

完整键、比较列、约0.001比例、固定种子、编码/算法版本、频率、样本量/字节预算和跨云授权。

持续覆盖：所有已约定分区均纳入COUNT轮巡；新分区默认确认后加入新清单版本。历史范围仍可能回刷，需周期复查。两端都缺失且从未登记的历史范围无法凭当前元数据补出。指标字段、分组字段及函数走白名单，过滤值参数化，禁止任意SQL / DSN输入。

确认范围不等于确认两端已同步，也不要求先提供血缘或停写证明。04 / 09
05 / DETERMINISTIC SAMPLING

“每1000行抽1行”：两端必须选同一规则的样本

本稿采用工程建议口径：约0.1%的确定性键抽样，不是严格每1000条恰好取1条。具体函数与编码须在两端版本上通过兼容性测试后启用。

概念规则，不是可直接执行的StarRocks SQL： H(固定种子 + 规范化完整键) → 非负整数 → 对1000取余 = 0 华为SR：在指定分区执行上述过滤，只返回命中行的键与约定列 阿里SR：对自己的相同逻辑范围独立执行同一规则 阿里ECS：比较双方样本键并集 → 同键行规范化 → 指纹比较

编码必须无歧义，明确类型、NULL、长度、字段顺序、整数/DECIMAL和时间精度。样本行指纹包含完整键与约定内容列；不能直接拼字符串或只哈希主键。首期建议统一在ECS算样本指纹，避免两端SQL序列化差异。

为什么不能各抽各的

自然顺序、RAND、LIMIT/OFFSET无法保证样本可配对。按序号每千条选一条，一端缺行可能使后续样本错位。两端独立按共同键规则选取，才能保留命中的单侧额外键。

没有可靠唯一键怎么办

Duplicate表排序键不等于唯一键。无唯一键、键含NULL或重复语义未确认时，第三档标为不适用/待定，保留COUNT和指标；不能静默换成随机抽样或全量拉取。

抽样完成，不等于全表内容检查完成

需要说明的限制处理方式
少量错误容易漏检按独立、近似均匀的键入样假设，1条错误命中概率约0.1%；1000条不同键错误，至少命中1条约63.2%。不构成客户数据检出率承诺。
小分区可能抽到0行双端0样本不算内容验证通过；标“样本不足”。可另外批准小范围全读或调整采样率，不悄悄改变规则。
固定样本不是累积全覆盖固定种子有利复查，但反复执行仍偏向同一批键；如需轮换种子，须双端同步并生成新规则版本，不能宣称轮巡必然查全。
服务端过滤不保证少扫描hash(key)谓词可能仍读取整分区键列，并消耗CPU；是否少读其他列，必须测扫描字节和查询执行信息。

结果完整性：样本只传完一部分、查询失败、超过样本预算或类型不支持都不能报相同。确认完整后按键规范顺序计算摘要；空结果与样本不足分开。普通指纹不是匿名化，样本字段与键必须获批。

0.1%指行的预期抽样比例，不是字节比例、差异容忍率或全表一致置信度。05 / 09
06 / OPERATIONS & EVIDENCE

控制能力保留，三类检查分别展示覆盖

轻量Web仍管理表、分区和诊断分片。减少默认校验深度，不减少任务可控性和证据留存。

调度

优先级先于分层

0–100越大越先；同级ODS先于DWD，再按队列顺序。不等待全部ODS通过，不推断血缘。

规则

深度、优先级、频率独立

重要表可高优先级COUNT而低频抽样；三类周期分别配置，避免把所有表高频全扫。

周期

定时与连续轮巡

支持日历、固定间隔、完成后休息再启动；未完跳过或合并，避免任务无限积压。

控制动作保留的行为新版重点
优先级 / 暂停调优先级不抢占；暂停不新开观察，已开始的双端观察可排空。COUNT、指标与抽样可分别启停；本次/后续范围明确。
取消 / 归档请求取消两端SQL，确认前显示“取消中”；归档是逻辑操作，不删SR数据。网络断开不代表服务端SQL已停；不清失败或缩小旧分母。
恢复 / 重生成恢复可见不自动复活旧查询；重生成新任务，保留历史证据。改指标、采样键/种子/比例要形成新规则版本。
手工局部细查指定表、分区、共同键范围或异常片，更小范围重新比对。抽样差异先局部复查；全量明细/全字段深查另批预算，不默认全表升级。

看板不能把三个“相同”混在一起

  • COUNT：全部约定范围中，应验、完成、数量相同、差异、失败及最老未验年龄。
  • 指标：配置了哪些指标、完整返回的组数、差异组、缺组、未知/超预算项。
  • 抽样：启用范围、样本行数/比例、样本键差、指纹差、样本不足与未支持项。

例如100个应验COUNT范围，90相同、5差异、5失败：完成率95%，观察相同覆盖率90%。抽样已执行100%仅代表计划完成，不代表100%行已比较。未知清单不能报全库100%。

仍是在线观察。报告保留两端读取时间和规则。COUNT、指标、抽样可能是不同SQL，不是同一快照；新增读取成对发起新观察，不将一端新结果与另一端旧结果拼接后宣称相同。
只报告本轮数量 / 指标 / 样本观察相同、不同或不可判定。06 / 09
07 / NETWORK & COMPUTE BUDGET

网络会轻很多，但先说清“和谁比”

优化把全量结果传输改为小结果和样本传输；数据库侧仍需计数、聚合、选样本。

比较基线新版的变化正确结论
单机跨云拉全量明细改为SR端聚合/抽样，ECS仅接收结果与命中样本。通常大幅降低跨云传输。前提是不能先拉全量再抽样。
旧双Worker本云全量指纹旧方案多只传摘要；新版可能跨云传样本字段。新版未必传得更少。主要减少一台主机与大量全字段处理；少部署与少传输不是同一指标。
SR生产资源COUNT、指标和hash过滤仍使用SR的CPU、IO、聚合资源。网络缩小不等于扫描缩小1000倍。三类SQL还可能重复扫描，需测后合并兼容查询或错峰。

样本有多大？用“行数 × 返回列宽”估算

约1万行

1000万行分区按0.1%入样，期望约1万行，不保证恰好此数。

约10MB

同例每个样本键＋返回列平均1000字节，华为→ECS约10MB。

约1GB

10亿行、相同列宽与比例，单次样本返回约1GB，仍需限流与预算。

示例使用十进制单位，未含协议、压缩、重试与分组结果。200TB目前口径未确认，不能直接认定传输200GB；只有当200TB是单端所选列的相应逻辑序列化量，且行宽/入样近似均匀时，乘0.001才有粗估意义。

单轮跨云量 ≈ 华为计数结果 + 华为分组指标结果 + 华为命中样本字节 + 协议/重试 传输时间下界 ≈ 跨云字节 ÷ 专线实际可用吞吐（不是线路标称带宽）

四项预算分别设置：SR查询并发/扫描时长；分组数与结果字节；样本与诊断字节；ECS内存/临时空间。超限要标未完成并调整计划，不能LIMIT截断后判相同。高基数分组不因改成Worker就自动变小。

成本：阿里校验ECS、PG/备份、少量临时材料、两端SR额外负载、专线实际计费及开发运维。单端方案是简化候选，不是已验证最便宜或容量够用。

COUNT准确行数不等于免费元数据查询；SHOW类统计值不代替精确COUNT。07 / 09
08 / PROOF OF CONCEPT

PoC先验证：可以不装华为Worker吗？

建议10–20张代表表，覆盖大/小分区、宽表、各表模型、有键/无键、核心指标和历史回刷。以下均需获批环境执行。

验证项怎么验放行证据
① 规则与范围导入名单，验证分区并集、单侧缺表/分区、NULL、未知及新增范围。范围可解释、失败/未知不被当成0或从分母消失。
② 指标正确性隔离表构造NULL、金额变化/抵消、缺组与高基数分组。该检出的指标差异被发现；抵消盲区被解释；超预算不截断通过。
③ 确定性抽样两端相同键数据验证命中集合一致；覆盖大整数、复合键、重复/空键和空样本。分别构造入样/未入样错误。算法与编码兼容；样本键并集和入样错误可检出；未入样错误允许漏检且明确说明。
④ 负载与传输测COUNT、聚合、服务端抽样的扫描量/耗时、返回字节、专线吞吐和业务延迟。没有全量拉回再抽样；三类轮巡可在批准窗口内完成并留余量。
⑤ 控制与恢复测试优先级、暂停、取消确认、超预算、中断重试、重复结果与PG恢复。不把半结果报相同；重采成对留新证据；取消不复活，旧证据可追溯。
不改真实订单制造差异，不中断生产专线来测试。已知真值和安全负测使用隔离表/材料；线上只读样本用于适配与负载评估，不预设两端一定相同。检测概率是设计解释，不替代真实PoC。

试验后的三种决定

采用单端执行

只读/TLS可用，SR端抽样一致，样本获准外传，资源和覆盖窗口可接受。

保留混合 / 双Worker

部分表需本云规范化、不能外传样本或深查量大。按资产选择执行位置，额外扫描成本仍需评估。

先调整，不扩大

减并发/频率、调整指标维度或列集合；不支持表明确登记，不降标准后冒充全范围内容通过。

PoC通过证明路径可用，不自动证明全库逐行一致或允许切流。08 / 09
09 / ALIGNMENT & NEXT STEPS

客户会议：确认检查深度与资源承诺

无需千表手写业务SQL。先给全量名单，再补少量核心指标与抽样表规则。

  • 1. 接受三档证据边界所有表COUNT；指定表加指标或抽样。接受0.1%抽样会漏掉未命中错误，不作为全表内容完整证明。
  • 2. 确认表、范围与配置分层CSV、优先级、范围排除；核心指标字段/函数/维度/精度；抽样完整键、比较列、固定种子和版本。
  • 3. 批准单端PoC与数据访问两端SR版本和只读端点、TLS、专线白名单；ECS保存双端凭证及接收样本/分组值的授权。
